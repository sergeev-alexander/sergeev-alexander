# Вложенные классы (Nested Classes) в Java

> **Nested class (вложенный класс)** в Java — это класс, определенный внутри другого класса.
> Вложенные классы используются для логической группировки классов и улучшения структуры кода.
>
> **Золотое правило:** Вложенный класс должен создаваться только для того, чтобы обслуживать обрамляющий его класс. Если
> вложенный класс оказывается полезен в каком-либо ином контексте, он должен стать классом верхнего уровня (top-level).

- ### Логическая организация кода:

  Вложенные классы используются для группировки классов, которые логически связаны между собой. Это может повысить
  читаемость и понимание кода.

- ### Инкапсуляция:

  Вложенные классы могут быть использованы для инкапсуляции логически связанных классов и скрытия их деталей
  реализации от внешнего кода.

- ### Уменьшение видимости:

  Если вложенный класс объявлен как private, его члены будут недоступны за пределами внешнего класса, что может
  уменьшить видимость и предоставить лучшее управление доступом.

- ### Использование внутри другого класса:

  Вложенные классы часто используются, когда класс имеет смысл только в контексте другого класса. Это позволяет
  сделать код более локализованным и уменьшить глобальное пространство имен.

- ### Упрощение структуры кода:

  Вложенные классы могут использоваться для упрощения структуры кода и избежания создания большого количества
  небольших файлов классов.

## 1. Иерархия классов в Java

## 2. Концепция и назначение

Вложенные классы имеют доступ ко всем (в том числе приватным) полям и методам внешнего класса, но не наоборот. Из-за
этого разрешения использование вложенных классов приводит к некоторому нарушению строгой инкапсуляции, однако это дает
следующие преимущества:

- **Логическая организация кода:** Используются для группировки классов, которые логически связаны между собой. Это
  повышает читаемость и понимание кода.
- **Инкапсуляция:** Позволяют скрыть детали реализации вспомогательных классов от внешнего кода.
- **Уменьшение видимости:** Если вложенный класс объявлен как `private`, его члены будут недоступны за пределами
  внешнего класса, что предоставляет лучшее управление доступом.
- **Локализация:** Часто используются, когда класс имеет смысл только в контексте другого класса. Это уменьшает
  глобальное пространство имен.
- **Упрощение структуры:** Помогают избежать создания большого количества небольших файлов классов.

## 3. Категории вложенных классов

Существуют четыре категории вложенных классов. Такие категории, за исключением статических, также называют **внутренними (Inner class)**.

**Важное отличие:** Внутренние классы ассоциируются не с самим внешним классом, а с конкретным *экземпляром* внешнего
класса.

### 3.1. Static nested class (Статический вложенный класс)

> **Когда использовать:** Когда нужна логическая группировка, но без привязки к экземпляру внешнего класса. 
> 
> В случае, если ссылка на обрамляющий класс не требуется — лучше сделать такой класс статическим.
>
> **Применение:** Вспомогательные классы (например, `Entry` в `Map`), билдеры, классы конфигурации, кэширование.

```java
public class Database {

    private String url;

    // Статический вложенный класс - не зависит от конкретного экземпляра Database
    public static class Config {

        private String host;
        private int port;

        public Config(String host, int port) {
            this.host = host;
            this.port = port;
        }

        // Может обращаться к private-членам Database!
        private String buildUrl() {
            return "jdbc:postgresql://" + host + ":" + port;
        }
    }

    public Database(Config config) {
        // Доступ к private-методу статического вложенного класса!
        this.url = config.buildUrl();
    }
}

// Использование:
// Обращаемся через имя внешнего класса, экземпляр Database не нужен
Database.Config cfg = new Database.Config("localhost", 5432);
Database db = new Database(cfg);
```

**Преимущества:**

- **Компактно:** `Config` «живёт» внутри `Database`, но не создаёт overhead.
- **Безопасно:** Никаких скрытых ссылок на внешний экземпляр → нет риска утечки памяти.
- **Полный доступ:** Имеет доступ к `private` членам внешнего класса (даже если сам `Config` объявлен как `public`).

### 3.2. Member inner class (Простой внутренний класс)

> **Когда использовать:** Когда объект внутреннего класса логически принадлежит экземпляру внешнего. 
> 
> Если каждому экземпляру такого класса необходима ссылка на включающий его экземпляр.
> 
> **Применение:** Итераторы, слушатели событий, адаптеры, состояние, зависящее от внешнего объекта.

```java
public class Car {

    private String model;
    private int fuel = 50;

    // Внутренний класс - машина "владеет" двигателем
    public class Engine {

        public void start() {
            if (fuel > 0) {
                // Прямой доступ к приватным полям внешнего класса (model, fuel)
                System.out.println(model + " заводится!");
                fuel -= 5;
            }
        }

        // Явный доступ к внешнему экземпляру через специальный синтаксис
        public Car getCar() {
            return Car.this;
        }
    }

    public Engine getEngine() {
        // Создаётся "привязанным" к this (к текущему экземпляру Car)
        return new Engine();
    }
}

// Использование:
Car car = new Car("Tesla", 50);

// Экземпляр Engine "знает", что принадлежит конкретному car
Car.Engine engine = car.getEngine(); 
engine.start(); // -> Tesla заводится!
```

**Особенность создания извне:**
Нельзя создать внутренний класс без экземпляра внешнего класса.

```java
// Ошибка компиляции: "non-static class Engine cannot be referenced from a static context"
Car.Engine e1 = new Car.Engine();

// Правильный синтаксис: outerInstance.new InnerClass()
Car car = new Car("BMW", 40);
Car.Engine e2 = car.new Engine(); 
```

### 3.3. Local inner class (Локальный класс)

> **Когда использовать:** Если класс необходим только внутри какого-то метода и требуется создавать экземпляры этого
> класса исключительно в границах этого метода.

Локальные классы объявляются внутри блока кода (обычно внутри метода). Они не могут иметь модификаторы доступа (
`public`, `private`, `protected`), так как их область видимости ограничена этим блоком.

```java
public class Calculator {

    public void calculate(int a, int b) {

        // Локальный класс объявляется прямо внутри метода
        class MathHelper {

            void printSum() {
                // Имеет доступ к параметрам метода, если они final / effectively final
                System.out.println("Sum: " + (a + b));
            }
        }

        // Создание и использование локального класса
        MathHelper helper = new MathHelper();
        helper.printSum();
    }
}
```

### 3.4. Anonymous inner class (Анонимный класс)

> **Когда использовать:** Если применение класса сводится к использованию лишь в одном месте и уже существует тип,
> характеризующий этот класс (интерфейс или абстрактный класс).
> 
> **Определение:** Локальный класс без имени, объявляемый прямо при создании экземпляра «на лету».

**Характеристики:**

- **Отсутствие имени:** Создаются непосредственно в месте использования.
- **Реализация/Расширение:** Часто используются для реализации интерфейсов или расширения абстрактных классов.
- **Ограниченная область видимости:** Могут использоваться только в том месте, где созданы.
- **Краткость:** Обеспечивают синтаксис для создания объектов с минимальным объемом кода.

#### Базовый синтаксис

```java
// 1. Реализация интерфейса (самый частый случай)
Runnable r = new Runnable() {
            @Override
            public void run() {
                System.out.println("Анонимный Runnable");
            }
        };
// Компилятор создаёт файл OuterClass$1.class, наследующий Runnable.

// 2. Расширение класса (встречается реже)
Thread t = new Thread() {
    @Override
    public void run() {
        System.out.println("Анонимный Thread");
    }
};

// Вывод появится асинхронно, в отдельном потоке.
t.start();
// Компилятор создаёт файл OuterClass$2.class, наследующий Thread.
```

#### Расширение абстрактного класса

От абстрактного класса нельзя создать объект напрямую, но можно создать анонимный подкласс, реализующий все `abstract`
методы:

```java
abstract class Animal {

    // Реализованный метод
    public void breathe() {
        System.out.println("Дышит");
    }

    // Абстрактный метод — должен быть реализован в подклассе
    public abstract void makeSound();
}

// Вместо создания именованного класса Dog/Cat, создаем подкласс "на месте"
Animal cat = new Animal() {
    @Override
    public void makeSound() {
        System.out.println("Мяу!");
    }
};

cat.makeSound(); // -> Мяу!
cat.breathe();   // -> Дышит (унаследовано от Animal)
```

#### Практические сценарии использования

| Сценарий                      | Пример                                                                        | Комментарий                                                                          |
|-------------------------------|-------------------------------------------------------------------------------|--------------------------------------------------------------------------------------|
| Инициализация коллекций       | `new HashSet<>() {{ add("a"); add("b"); }}`                                   | «Double-brace initialization» - **опасно** (утечки памяти, проблемы с сериализацией) |
| Захват переменных             | `int x = 42; Runnable r = new Runnable() { ... print(x); };`                  | Работает, если `x` является `final` или `effectively final`                          |
| Переопределение одного метода | `Button b = new Button("OK") { @Override protected void onClick() { ... } };` | Удобно, если нет лямбд или нужно переопределить метод конкретного класса             |
| Unit-тесты (Mockito)          | `doAnswer(new Answer<Void>() { ... })`                                        | В современном коде вытеснено лямбдами и `when().thenReturn()`                        |

#### Современная альтернатива

В современной Java (8+) анонимные классы для функциональных интерфейсов (интерфейсов с одним абстрактным методом)
практически полностью вытеснены **лямбда-выражениями**.

Анонимные классы нужны только если:

1. Нужно переопределить больше одного метода.
2. Нужен доступ к `protected` методам суперкласса.
3. Нужен явный тип для перегрузки методов или доступа к `this` самого анонимного класса.

## 4. Общие подводные камни

### 4.1. Скрытая ссылка и утечки памяти (Memory Leaks)

Внутренние и анонимные классы содержат **скрытую ссылку** (`this$0`) на экземпляр внешнего класса. Это может привести к
серьезным утечкам памяти.

```java
public class Heavy {

    // Большой объект - 1 МБ
    private final byte[] data = new byte[1_000_000];

    // Метод возвращает задачу (например, для пула потоков)
    public Runnable createTask() {
        // Здесь создаётся анонимный ВНУТРЕННИЙ класс.
        // Компилятор неявно генерирует скрытое поле this$0, ссылающееся на Heavy.
        return new Runnable() {
            @Override
            public void run() {
                System.out.println("Done");
            }
        };
    }
}
```

**Сценарий утечки:**

```java
public class Cache {
    // Долгоживущий кэш (например, статический список)
    private static final List<Runnable> TASKS = new ArrayList<>();

    public static void addTask(Runnable task) {
        TASKS.add(task);
    }
}

// Где-то в коде:
Heavy heavy = new Heavy();              // <- создаём "тяжёлый" объект
Runnable task = heavy.createTask();     // <- task "держит" ссылку на heavy!
Cache.addTask(task);                    // <- task попадает в статический список

heavy =null;                           // <- "забываем" heavy, но он НЕ СОБЕРЁТСЯ GC!
```

Объект `heavy` не может быть собран Garbage Collector'ом, потому что `task` содержит скрытую ссылку на него и хранится в
долгоживущем кэше.

**Как исправить:**
Используйте **лямбды**. Лямбда НЕ создаёт внутренний класс, если не захватывает `this` или поля внешнего класса.

```java
public Runnable createTask() {
    // ✅ Лямбда не держит ссылку на this (если она не используется внутри)
    return () -> System.out.println("Done");
}
```

Если всё же нужен именно класс (например, для сложной логики) — сделайте его статическим:

```java
public Runnable createTask() {
    // Локальный static-класс (доступно с Java 16+)
    static class DoneTask implements Runnable {
        @Override
        public void run() {
            System.out.println("Done");
        }
    }
    return new DoneTask();
}
```

### 4.2. Утечки памяти при Double-Brace Initialization

```java
public class Leaky {
    
    private final List<String> data = new ArrayList<>();

    public List<String> getCopy() {
        // ← создаётся анонимный класс, наследующий ArrayList
        return new ArrayList<>() {{
            addAll(data);                  // ← захватывает this (Leaky)
        }};
    }
}
```

Экземпляр анонимного класса держит ссылку на `Leaky`. Если список «утечёт» во внешний кэш, объект `Leaky` никогда не
будет удален сборщиком мусора.

### 4.3. Поведение `this` внутри анонимного класса

Ключевое слово `this` внутри анонимного класса ссылается на **экземпляр самого анонимного класса**, а не на внешний
класс.

```java
class Outer {
    
    void method() {
        Runnable r = new Runnable() {
            @Override
            public void run() {
                // Ссылается на экземпляр Runnable
                System.out.println(this);

                // Так можно добраться до внешнего экземпляра Outer
                System.out.println(Outer.this);
            }
        };
    }
}
```

### 4.4. Сложности с сериализацией

> Если внешний класс `Car` реализует `Serializable`, то внутренний класс `Engine` тоже должен реализовывать
`Serializable`, потому что при сериализации `Engine` требуется сериализовать и скрытую ссылку на `Car.this`.
>
> При десериализации сначала восстанавливается `Car`, потом - `Engine`, что усложняет процесс и может привести к
`InvalidClassException`, если версии не совпадают.

**Решение:** Используйте `static class Engine` — тогда `Engine` сериализуется независимо, без `Car`.

## 5. Best Practices (Рекомендации)

1. **Статический vs Нестатический:**

- `static class` = просто класс внутри другого (без привязки к экземпляру).
- `class` (без `static`) = кусочек состояния внешнего объекта.

  > **Правило:** Если вы не используете `Outer.this` и не обращаетесь к нестатическим полям внешнего класса — **всегда
  > делайте класс `static`**.

2. **Выносите наружу:**

- Если вложенный класс стал полезен в каком-либо ином контексте или стал слишком большим/сложным — вынесите его в
  отдельный файл (сделайте top-level).

3. **Избегайте Double-Brace инициализации:**

- Никогда не используйте `new HashSet<>() {{ add(...); }}`. Это источник утечек памяти и проблем с сериализацией.
  Используйте `List.of()`, `Map.of()` или `Set.of()`.

4. **Анонимные классы vs Лямбды:**

- Для функциональных интерфейсов (один абстрактный метод) всегда используйте лямбды. Они не создают лишних объектов в
  памяти и не держат скрытых ссылок.
- Анонимные и локальные классы оставляйте только для крайних случаев (нужно состояние, несколько методов, специфичный
  `this`).

5. **Помните про инкапсуляцию:**

- Вложенные классы нарушают строгую инкапсуляцию, имея доступ к `private` полям внешнего класса. Используйте это
  осознанно, только для тесно связанных компонентов (например, `Builder` или `Iterator`).
