# Конспект по теме «Сертификация информационных систем»

## 1. Сертификация средств и систем информатизации

Сертификация средств и систем информатизации — элемент общей системы сертификации продукции в Российской Федерации.

**Основные цели сертификации:**
- защита пользователей от приобретения опасных средств и систем, в том числе импортных;
- обеспечение разработчиков и пользователей достоверной информацией о рынке средств информатизации;
- обеспечение информационного обмена между государственными системами;
- обеспечение взаимодействия государственных и негосударственных субъектов;
- повышение научно-технического уровня и конкурентоспособности отечественных систем;
- создание условий для вхождения России в мировое информационное пространство.

**Выгоды для изготовителя/поставщика:**
- расширение рынка сбыта;
- подтверждение качества продукции по сравнению с конкурентами;
- создание доверительных отношений с потребителями.

**Сертификация ПО** — процесс оценки качества программных объектов на соответствие нормам и показателям, прописанным в нормативных документах.

В России обязательная сертификация ПО не предусмотрена — только добровольная.

---

## 2. Объекты сертификации

**Объектами сертификации являются:**
- классы и группы по ОКП 500000; ТН ВЭД 85; ТН ВЭД ЕАЭС 85; ОКУН 804000;
- ПО средств измерений (автономное и встроенное);
- ПО измерительных и информационно-измерительных систем, лабораторных систем (ЛИМС), в том числе на базе GPS, ГЛОНАСС;
- ПО контроллеров и вычислительных блоков;
- системные программные средства;
- прикладные программные средства научных исследований, идентификации, управления, учебного назначения;
- операционные системы и языки программирования;
- СУБД;
- программные средства для расчетов, моделирования, САПР, АСУ ТП, АРМ;
- программные средства защиты и восстановления информации;
- ПО электронных архивов, мультимедиа, умных устройств, блокчейн;
- аппаратное обеспечение программных средств;
- аппаратно-программные комплексы (АПК).

**Обязательной сертификации по ЭМС и безопасности подлежат:**
- вычислительные машины и комплексы;
- персональные ЭВМ;
- устройства внешней памяти, ввода-вывода и отображения информации;
- устройства подготовки и телеобработки данных.

Сертификация по требованиям электромагнитной совместимости и параметрам безопасности проводится Госстандартом России в системе ГОСТ Р.

## 3. Системы сертификации

**Основные системы:**
- **Система сертификации ГОСТ Р** — обязательная и добровольная сертификация; центральный орган — Госстандарт РФ.
- **РОСИНФОСЕРТ** — добровольная сертификация; создана на базе Роскоминформа.
- **Система сертификации Гостехкомиссии при Президенте РФ**.
- **Система сертификации Министерства обороны РФ**.
- **Система сертификации ФАПСИ**.

**Нормативная база включает три группы документов:**
1. нормативные документы на объекты сертификации;
2. нормативные документы на методы испытаний;
3. нормативные документы, регламентирующие процедуры сертификации.

**Основные направления сертификации:**
- обязательная сертификация по ЭМС и безопасности;
- обязательная сертификация средств защиты информации;
- добровольная сертификация функциональных параметров.

**Добровольная сертификация** проводится для повышения конкурентоспособности, расширения сферы использования и получения экономических преимуществ. Может проводиться в системе ГОСТ Р и других системах, зарегистрированных Госстандартом.

## 4. Уровни качества программной продукции

**Качество** — количественная или качественная степень соответствия характеристик объекта потребностям или ожиданиям пользователя.

**Система качества** — структурированный набор документов, регламентирующий аспекты производственной деятельности предприятия.

**Международные стандарты:**
- ISO 9126:1-4 «Характеристики и метрики качества программного обеспечения»;
- ISO 14598-1-6:1998-2000 «Оценивание программного продукта».

**ISO 9126 состоит из четырёх частей:**
1. Модель качества.
2. Внешние метрики.
3. Внутренние метрики.
4. Метрики качества в использовании.

**Метрики:**
- внешние — определяются на основе поведения системы в процессе испытаний и эксплуатации;
- внутренние — применяются к неисполняемым компонентам (спецификация, исходный текст);
- качество в использовании — измеряет степень удовлетворения потребностей пользователей.

**ГОСТ 2844-94:** качество ПО — совокупность свойств, обеспечивающих способность удовлетворять потребности заказчика; главный показатель — надёжность.

**ISO/IEC 12207** определяет основные и организационные процессы ЖЦ ПО.

**Контроль качества ПО на этапах ЖЦ:**
- проверка соответствия требований и критериев их достижения;
- верификация и валидация промежуточных результатов;
- тестирование готового ПО, сбор данных об отказах и дефектах;
- подбор моделей надёжности;
- оценка показателей качества.

**Модель качества ПО имеет четыре уровня:**
1. Определение характеристик качества ПО.
2. Определение атрибутов для конкретной характеристики.
3. Измерение качества с помощью метрик.
4. Оценивание значений атрибутов.

**Шесть основных характеристик качества ПО:**
1. **Функциональность** — пригодность, корректность, интероперабельность, защищённость, соответствие.
2. **Надёжность** — завершённость, устойчивость к ошибкам, восстанавливаемость, доступность, соответствие.
3. **Практичность (удобство)** — понятность, обучаемость, простота использования, привлекательность, соответствие.
4. **Эффективность** — временная эффективность, ресурсоёмкость, соответствие.
5. **Сопровождаемость** — анализируемость, изменяемость, стабильность, тестируемость, соответствие.
6. **Переносимость** — адаптируемость, простота установки, сосуществование, взаимозаменяемость, соответствие.

## 5. Оценка качества программных средств

Оценка качества осуществляется на всех этапах ЖЦ ПС:
- при планировании показателей качества;
- при контроле на этапах разработки;
- при контроле в процессе производства;
- при проверке эффективности модификации на этапе сопровождения.

**Оценка качества ПС** — совокупность операций: выбор номенклатуры показателей, определение их значений и сравнение с базовыми значениями.

**Оценку проводят:**
- разработчик — на этапах разработки;
- фондодержатель — при приёмке в фонд;
- испытательные центры и центры сертификации — на этапах испытаний и внедрения;
- изготовитель — на этапах тиражирования;
- пользователь — на этапах внедрения, сопровождения и эксплуатации.

**Основные задачи оценки качества:**
- планирование уровня качества;
- контроль значений показателей;
- эксплуатационный контроль;
- выбор базовых образцов;
- методическое руководство разработкой нормативных документов.

**Методы определения показателей качества ПС:**
- **по способам получения информации:** измерительный, регистрационный, органолептический, расчётный;
- **по источникам получения информации:** традиционный, экспертный, социологический.

**Социологические методы сбора информации:**
- анализ документов;
- социологическое наблюдение;
- опрос (анкетирование, интервьюирование, экспертный опрос);
- социальный эксперимент;
- социально-психологические методики.

**Экспертный опрос** — выявление наиболее существенных аспектов проблемы и повышение надёжности информации за счёт знаний экспертов.

Оценка качества ПС — основа аттестации программного продукта. Используются ГОСТ 28806-90, ГОСТ 28195-89.

**Процесс сертификации ПС включает этапы:**
1. Подача заявки в орган по сертификации.
2. Принятие решения по заявке, назначение экспертов.
3. Оформление договора.
4. Разработка и согласование методики сертификационных испытаний.
5. Проведение испытаний: технологический этап и оценка экспертами.
6. Принятие решения о выдаче сертификата или об отказе.

**Выбор номенклатуры показателей качества** осуществляется с учётом назначения и области применения ПС. По ГОСТ 28195-89 выделено 11 групп программных средств и группа 509 «Прочие ПС».

**Этапы оценки качества:**
- выбор основных показателей качества;
- выбор этапа ЖЦ ПС;
- расчёт выбранных показателей;
- обработка экспертных оценок;
- расчёт оценки по факторам качества;
- расчёт комплексной оценки качества ПС;
- вывод результатов.

**Формализованная модель:**  
A = <X, P→N, H(N), R(N), O>,  
где X — входные параметры; P→N — нечёткая импликация; N — группа показателей качества; H — множество экспертных оценок; R — множество расчётных оценок; O — множество экспертных оценок для определения превосходства факторов.

**Диаграммы потоков данных:**
- нулевой уровень — процесс оценивания качества;
- первый уровень — подпроцессы: рассмотрение заявления, проведение оценивания, оформление документов;
- второй уровень — 5 этапов: определение фазы ЖЦ, выбор групп ПС, подготовительные работы, оценивание, подведение итогов.

**Фазы ЖЦ по ГОСТ 28195-89:** анализ, проектирование, реализация, тестирование, изготовление, внедрение, эксплуатация, обслуживание.

Для выбора группы ПС используется метод дерева решений. Атрибуты ПС: тип, возможность использования в разных областях, многозадачность, поддержка работоспособности других ПС, основная задача, ориентированность, возможность создания других ПО, возможность доработок, область применения.

**Реализация в 1С:** формы «Выбор группы программных средств», «Показатели для оценки качества ПС», «Расчет комплексной оценки качества ПС». Вкладки: Цель, Критерии, Альтернативы, Сравнение критериев, Сравнение альтернатив, Результат. Используется метод анализа иерархий (МАИ).

## 6. Сертификаты безопасности

**Сертификат безопасности** — документ, подтверждающий соответствие продукции нормам и требованиям безопасности.

**Основание для выдачи** — протокол испытаний аккредитованных лабораторий, независимая экспертиза.

**Сертификат содержит:**
- информацию о продукции;
- сведения об изготовителе или поставщике;
- нормативные документы;
- сведения об органе по сертификации;
- срок действия;
- основания для выдачи.

**Срок действия:** от 1 года до 3 лет; бывают «одноразовые» на партию продукции.

**Бланки:**
- обязательная сертификация — жёлтый бланк;
- добровольная — голубой бланк.

**Приостановление действия** возможно при:
- непрохождении инспекционного контроля;
- технической ошибке;
- недостоверности информации;
- ликвидации производства.

Возобновление — после устранения нарушений.

**Реестр сертификатов:** fsa.gov.ru.  
**Статусы:** действует (зелёный), приостановлен (оранжевый), аннулирован (красный), архивный.

## 7. Сертификат SSL

**SSL (Secure Socket Layer)** — стандартная интернет-технология безопасности, обеспечивающая зашифрованное соединение между веб-сервером и браузером. Позволяет использовать HTTPS.

**Назначение:** защита данных при онлайн-транзакциях, передача конфиденциальной информации.

**Процесс:**
1. Браузер или сервер подключается к сайту, защищённому SSL.
2. Запрашивается идентификация веб-сервера.
3. Веб-сервер отправляет копию SSL-сертификата.
4. Проверяется доверенность сертификата.
5. Веб-сервер возвращает подтверждение с цифровой подписью.
6. Начинается зашифрованный сеанс.

**Признаки защищённого сайта:** HTTPS, значок замка.

**Сведения в SSL-сертификате:**
- доменное имя;
- владелец;
- центр сертификации;
- цифровая подпись центра;
- связанные поддомены;
- дата выдачи;
- срок действия;
- открытый ключ.

**Типы SSL-сертификатов:**
1. EV SSL — расширенная проверка.
2. OV SSL — подтверждение организации.
3. DV SSL — подтверждение домена.
4. Wildcard — защита домена и поддоменов.
5. Мультидоменные (MDC/SAN).
6. UCC — унифицированные коммуникации.

**Получение:**
- самоподписной (бесплатный, но вызывает предупреждения браузеров);
- платный — от центра сертификации.

**Шаги получения:**
1. Подготовка.
2. Создание CSR.
3. Отправка запроса в центр сертификации.
4. Установка сертификата.

**Срок действия:** не более 27 месяцев (2 года + 3 месяца). С 2020 года Google, Apple и Mozilla применяют годовые сертификаты. По истечении срока сайт становится небезопасным.

**Рекомендации по безопасности:** проверять адрес, значки, политику конфиденциальности; остерегаться фишинговых атак.

## 8. Сертификат разработчика (Code Signing)

**Сертификат разработчика** — сертификат, которым подписывается ПО или скрипты. Подтверждает автора и гарантирует, что код не был изменён после подписания.

**Гарантирует:**
- подлинность источника;
- целостность кода.

Без цифровой подписи Windows выдаёт предупреждение «Неизвестный издатель».

**Виды сертификатов по центрам сертификации:**
- Symantec, Thawte, Comodo, Digicert, Globalsign, Trustwave, Startcom.

**Платформы:**
- Microsoft Authenticode;
- Code Signing for Apple;
- Microsoft VBA Signing;
- Java Code Signing;
- Adobe Air Signing;
- Kernel Mode Signing;
- Android;
- Windows Phone;
- Qualcomm BREW.

**Процесс подписи кода:**
1. Разработчик запрашивает Code Signing сертификат.
2. Создаётся хеш кода (MD5 или SHA).
3. Хеш шифруется приватным ключом.
4. Формируется пакет: код + зашифрованный хеш + сертификат издателя.

**Процесс проверки подписанного кода:**
1. Проверка сертификата издателя.
2. Создание нового хеша.
3. Расшифровка хеша публичным ключом.
4. Сравнение двух хешей.

Если хеши не совпадают — ПО могло быть модифицировано.

**Timestamp (временная метка)** — указывает время подписи. Позволяет проверять подпись после истечения срока сертификата. Проверяется через TSA (Timestamping Authority).

**Пример:**
- сертификат действителен: 01.01.2020–31.12.2022;
- подпись сделана: 04.07.2022;
- проверка: 30.04.2023.

С временной меткой подпись пройдёт проверку, без неё — нет.
